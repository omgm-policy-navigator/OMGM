# Analysis Phase D4 Plan

## 목표

검수된 정책 문서를 설명 목적의 단일 의미 Chunk로 분리하고, 출처 추적이 가능한 임베딩 입력 Seed를 만든다.

## 범위

- 제목, 조항, 문단과 문장 의미 변화에 따른 분할
- Markdown 표의 헤더 보존 및 데이터 행별 Chunk 변환
- 문서 유형과 Chunk 의미 유형 분류
- 정책·문서 ID, 원문 URL·위치와 콘텐츠 해시 연결
- 혼합 의미, 과도한 길이, 불충분한 문맥 품질 검수
- 승인된 Chunk만 포함하는 임베딩 Seed 계약과 CSV 기준본

## 완료 기준

- 신청 조건과 신청 방법이 별도 의미 Chunk로 분리된다.
- 표의 각 데이터 행이 헤더 문맥을 가진 독립 Chunk가 된다.
- 모든 Chunk가 정책·문서 ID, 원문 URL과 위치를 가진다.
- `REVIEW_REQUIRED` Chunk는 임베딩 Seed 생성에서 제외된다.
- 실제 저장소 검증 명령을 실행해 결과를 기록한다.

## 제외 범위

- 외부 정책 원문 수집과 PDF·HTML 파싱
- 실제 임베딩 벡터 생성
- pgvector 테이블과 적재 migration
- 검색·RAG API와 최종 자격 판정
