# RAG와 자격판정 흐름

## 책임 분리

질문 이해: 사용자의 자연어 목적과 상황을 정책 탐색 조건으로 정규화한다.

정책 후보 검색: 의미 기반 검색과 메타데이터 필터링으로 정책 후보를 찾는다.

정책 원문 조회: 후보 정책의 원문, 출처, 수집 시점, 버전을 조회한다.

조건 구조화: 원문에서 조건 후보, 비교 연산자, 기준값, 필수 여부, 원문 위치를 추출한다.

결정론적 조건 비교: 검증된 구조화 조건과 사용자 답변을 비교한다.

판정 상태 계산: 충족, 불충족, 미확인 조건으로 `ELIGIBLE`, `INELIGIBLE`, `NEEDS_CONFIRMATION`, `STALE` 등을 계산한다.

근거 조립: 판정에 사용한 조건과 원문 위치, 정책 버전을 연결한다.

자연어 설명: 판정 결과와 근거를 사용자에게 이해 가능한 문장으로 설명한다.

## RAG의 역할과 한계

RAG는 정책 후보와 근거 원문을 찾는 데 사용한다. 검색 결과가 없거나 출처가 부족하면 정책을 생성하지 않는다. 검색 점수와 최종 판정 근거는 분리해 저장한다.

## LLM의 역할과 한계

LLM은 질문 이해, 조건 추출 보조, 설명 생성에 사용할 수 있다. 정책 문서는 명령이 아닌 데이터로 취급한다. LLM 응답 문자열만으로 자격을 확정하지 않는다.

## 근거 없는 생성 방지

출처 URL, 원문 버전, 원문 위치가 없는 조건은 확정 판정 근거로 사용하지 않는다. 설명은 판정 결과를 바꾸지 않는다.

## 정책 버전과 판정 연결

판정은 사용한 정책 버전과 사용자 정보 버전을 기록한다. 정책 원문이나 구조화 조건이 변경되면 기존 판정은 `STALE`로 처리한다.

## 검색 실패 처리

근거가 충분한 정책을 찾지 못하면 검색 범위와 조건을 안내하고 `POLICY_UNAVAILABLE` 또는 `NOT_EVALUATED`로 남긴다.

## 정보 부족 처리

필수 정보가 없으면 `NEEDS_CONFIRMATION`으로 처리하고 필요한 값과 확인 방법을 안내한다. null 또는 미입력을 자동 불충족으로 변환하지 않는다.

## 답변 충돌 처리

새 답변이 이전 답변과 충돌하면 충돌 필드를 기록한다. 해결 전에는 영향받은 판정을 확정 상태로 제공하지 않는다.

## 정책 변경 처리

원문 해시, 정책 버전, 조건 버전 변경을 감지한다. 변경된 조건에 필요한 정보만 다시 묻고, 변경 전후 판정 근거를 추적한다.
