# 예외 처리

## 정보 부족

탐지 조건: 필수 조건에 필요한 값이 없거나 사용자가 모른다고 답한다.

내부 상태: `NEEDS_CONFIRMATION`.

사용자 응답: 필요한 값, 기준, 확인 가능한 서류를 안내한다.

재시도 가능 여부: 가능.

기존 판정 처리: 확정 판정으로 제공하지 않는다.

로그 수준: INFO.

민감정보 처리: 미입력 값과 안내만 기록하고 실제 소득·자산 원문은 로그에 남기지 않는다.

## 모호한 답변

탐지 조건: 답변이 정책 조건의 단위나 기준일과 맞지 않는다.

내부 상태: `NEEDS_CONFIRMATION`.

사용자 응답: 필요한 단위와 기준일을 재질문한다.

재시도 가능 여부: 가능.

기존 판정 처리: 영향받은 조건만 보류한다.

로그 수준: INFO.

민감정보 처리: 원문 답변 대신 필드명과 상태만 기록한다.

## 답변 충돌

탐지 조건: 새 답변이 이전 답변 또는 저장된 사실과 충돌한다.

내부 상태: `CONFLICTED`.

사용자 응답: 충돌한 항목을 설명하고 현재 상태를 재확인한다.

재시도 가능 여부: 가능.

기존 판정 처리: 영향받은 판정을 무효화한다.

로그 수준: WARNING.

민감정보 처리: 변경 전후 값은 감사 저장소에 최소 범위로 남기고 일반 로그에는 남기지 않는다.

## 정책 원문 변경

탐지 조건: 원문 해시, 정책 버전, 구조화 조건이 변경된다.

내부 상태: `STALE`.

사용자 응답: 정책 기준 변경과 필요한 추가 확인 항목을 안내한다.

재시도 가능 여부: 가능.

기존 판정 처리: 최신 판정으로 표시하지 않는다.

로그 수준: INFO.

민감정보 처리: 정책 변경 로그에는 사용자 개인정보를 포함하지 않는다.

## 정책 파싱 실패

탐지 조건: 원문에서 조건을 구조화할 수 없거나 검증되지 않았다.

내부 상태: `NOT_EVALUATED`.

사용자 응답: 근거 부족 또는 확인 필요로 안내한다.

재시도 가능 여부: 원문 또는 구조화 규칙 보완 후 가능.

기존 판정 처리: 확정 판정 근거로 사용하지 않는다.

로그 수준: WARNING.

민감정보 처리: 정책 원문과 사용자 답변을 분리한다.

## 검색 결과 없음 또는 근거 부족

탐지 조건: 정책 후보가 없거나 출처가 없는 결과만 있다.

내부 상태: `POLICY_UNAVAILABLE`.

사용자 응답: 검색 범위와 조건을 안내한다.

재시도 가능 여부: 검색 조건 또는 데이터 범위 보완 후 가능.

기존 판정 처리: 새 판정을 만들지 않는다.

로그 수준: INFO.

민감정보 처리: 검색 조건은 최소화해 기록한다.

## 외부 시스템 장애

탐지 조건: 정책 출처, DB, 벡터 저장소, LLM Provider 호출 실패.

내부 상태: 기능별 일시 실패.

사용자 응답: 재시도 가능 여부와 현재 가능한 범위를 안내한다.

재시도 가능 여부: 장애 유형에 따라 가능.

기존 판정 처리: 이미 저장된 최신 판정만 버전과 함께 표시한다.

로그 수준: ERROR.

민감정보 처리: 요청 본문과 Secret을 로그에 남기지 않는다.

민감정보 처리: 입력값 원문 대신 필드명과 오류 코드 중심으로 기록한다.
