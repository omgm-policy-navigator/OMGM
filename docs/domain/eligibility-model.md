# 자격판정 모델

## 판정 입력

- 구조화된 정책 조건.
- 사용자 답변과 확정 여부.
- `policy_version`.
- 사용자 정보 버전.
- 기준일.

## 판정 출력

- 정책명과 정책 식별자.
- 신청 가능성 상태.
- 평가 생명주기 상태.
- 충족 조건.
- 불충족 조건.
- 확인 필요 조건.
- 필요한 서류.
- 정책 원문 출처.
- 정책 버전 식별자.
- 행정기관 최종 심사와 다를 수 있다는 안내.

## 신청 가능성 상태

- `LIKELY_ELIGIBLE`: 현재 확보한 정보가 신청 가능 조건을 충족할 가능성이 높다.
- `NEEDS_CONFIRMATION`: 필수 정보가 없거나 사용자가 정확한 값을 알지 못한다.
- `AVAILABLE_LATER`: 신청 기간이나 기준일 때문에 이후 확인 또는 신청 가능성이 있다.
- `LIKELY_INELIGIBLE`: 명확한 필수 조건 불충족이 존재한다.
- `OFFICIAL_CONFIRMATION_REQUIRED`: 서비스가 더 이상 확정할 수 없고 행정기관 확인이 필요하다.

## 평가 생명주기 상태

- `ACTIVE`: 현재 정책 버전과 사용자 정보 버전 기준으로 유효한 평가다.
- `STALE`: 정책 원문, 구조화 조건, 판정 규칙, 기준 버전이 변경되었다.
- `CONFLICTED`: 답변이 이전 답변 또는 저장된 사실과 충돌한다. 사용자에게는 재확인 요청으로 표현할 수 있다.
- `NOT_EVALUATED`: 아직 판정하지 않았다.

## 조건 평가 규칙

필수 조건이 충족되면 충족 조건에 기록한다. 필수 조건이 명확히 불충족되면 `LIKELY_INELIGIBLE`이다. 필수 조건 값이 없거나 미확정이면 `NEEDS_CONFIRMATION`이다.

선택 조건은 정책 설명이나 우선순위에 영향을 줄 수 있으나 필수 조건처럼 자동 탈락시키지 않는다.

## 정보 부족과 불충족의 차이

정보 부족은 사용자가 값을 제공하지 않았거나 정확성을 확정하지 못한 상태다. 불충족은 확보된 확정 정보가 정책 기준을 명확히 만족하지 못하는 상태다.

## 판정 버전

판정은 사용한 `policy_version`과 사용자 정보 버전을 저장해야 한다. 어느 한쪽이 바뀌면 영향받은 판정을 `STALE`로 두고 재검토한다.

## 재판정 조건

- 사용자 답변 변경.
- 답변 충돌 해결.
- 정책 원문 변경.
- 구조화 조건 변경.
- 판정 규칙 변경.
- 기준일 변경.

## 최종 행정심사와의 차이

서비스 판정은 안내이며 행정기관의 최종 승인, 지급, 수혜를 보장하지 않는다.
